# PR : feat(llm): usage → model routing with pinned exact versions (P74, issue #180, ADR-0108)

- Date : 2026-11-21
- Branche : feat/180-p74-routing
- Issue : #180
- ADR : docs/decisions/adr-0108-llm-usage-model-routing.md

## Livré

- `src/petrichor/llm/routing.py` (nouveau) : table versionnée
  `USAGE_MODEL_ROUTING` `{usage: {model, version}}` épinglée —
  `semantic-profile`/`cluster` → `mistral-large-4-2510`,
  `reading`/`clarification` → `mistral-small-2603`,
  `narration` → `ministral-14b-2512` (repli épinglé `mistral-small-2603`).
  `ModelRoute` (pydantic, frozen, extra=forbid) rejette tout alias
  `-latest` ; `validate_routing` lève un `RoutingError` typé.
- `MistralProvider` prend la routing en constructeur et route chaque
  appel par usage ; l'archive et `usage_totals()` portent le couple
  (usage, modèle routé) avec la version exacte (rejeu P46) ;
  `routing_fingerprint()` expose la version épinglée par usage.
- Repli narration : si le modèle primaire dégrade, un second document
  est tenté sur le repli épinglé (log `llm_narration_fallback`).
- `PETRICHOR_LLM_MODEL` (dont le défaut était un alias `-latest`)
  supprimé de `ApiSettings` ; `main.py` construit le provider sans
  modèle unique.
- Tests : `tests/test_llm_routing.py` (table conforme annexe B §B.4,
  garde `-latest`, modèle routé par usage dans le corps de requête,
  archive/totaux par couple, repli narration) ; `tests/test_llm_mistral.py`
  mis à jour.

## Limites connues

- Le suffixe daté exact de Mistral Large 4 (`mistral-large-4-2510`)
  suit la convention YYMM du catalogue public (preview 2026-10) ;
  `mistral-small-2603` et `ministral-14b-2512` confirmés via la doc
  publique. À re-confirmer par `GET /v1/models` au déploiement
  (annexe B §B.4), comme prévu par la directive.
- Pas de multi-fournisseurs ni de choix de modèle à chaud (hors périmètre).
