# PR : feat(auth): OIDC access-token validation brick (PT-1, issue #182)

- Date : 2026-11-21
- Branche : feat/182-pt1-token-verification
- Issue : #182

## Livré

- `src/petrichor/auth/settings.py` (nouveau) : `AuthSettings`
  (pydantic-settings) lisant `AUTH_ISSUER`, `AUTH_CLIENT_ID`,
  `AUTH_CLIENT_SECRET`, `AUTH_ALLOWED_AUDIENCES`, `AUTH_DISABLED` ;
  `allowed_audiences()` retombe sur le `client_id` par défaut.
  Aucune URL d'endpoint en dur : seul l'émetteur est configuré, le
  discovery en dérive le reste.
- `src/petrichor/auth/verification.py` (nouveau) : `TokenVerifier` —
  discovery `{issuer}/.well-known/openid-configuration` (cache 24 h),
  JWKS (cache 1 h + un rafraîchissement forcé sur `kid` inconnu),
  vérification RS256 locale via **joserfc** (librairie JOSE maintenue,
  prescrite par l'issue #182), contrôles `iss` / `aud` / `exp` / `nbf`
  avec tolérance d'horloge 60 s. `verify_access_token` renvoie des
  `TokenClaims` typés (sub/iss/aud/exp/nbf) ; `enabled` reflète
  `AUTH_DISABLED` ; `close()` libère le client HTTP possédé.
- Erreur typée `TokenRejectedError(reason=...)` sur l'ensemble fermé
  `RejectionReason` (Literal, ADR-0006) avec une raison exacte par type
  d'échec (malformed_token, bad_signature, unknown_kid, invalid_token,
  expired, invalid_issuer, invalid_audience, invalid_not_before,
  invalid_claims, missing_claims, discovery_unavailable,
  discovery_without_jwks_uri, jwks_unavailable, auth_disabled) ;
  logs structurés `auth_token_rejected` / `auth_discovery_failed` /
  `auth_jwks_failed` (+ `auth_jwks_refresh_on_unknown_kid` en DEBUG),
  tous pinés par tests (ADR-0005).
- `AUTH_ISSUER` est requis depuis l'environnement : aucune valeur par
  défaut d'émetteur dans le code (review PR #201).
- `tests/test_auth_verification.py` (nouveau) : 18 tests déterministes,
  paire de clés RSA générée en fixture, `httpx.MockTransport` pour
  discovery + JWKS — niveau L1 (aucun réseau, aucun IdP, aucun Docker,
  conforme au niveau obligatoire en CI) : token valide, caches,
  audience liste / configurée, expiré, mauvaise aud/iss, mauvaise
  signature, `kid` inconnu (double fetch JWKS), malformé, échecs
  discovery/JWKS, claim `sub` manquante, mode désactivé.
- Dépendance ajoutée : `joserfc` (JOSE maintenue ; l'issue #182 prescrit
  explicitement authlib ou joserfc et exclut les libs non maintenues).
- `.env.example` : bloc `AUTH_*` documenté ; aucun secret réel commité.

## Review round 1 (PR #201)

4 BLOCKING corrigés : émetteur sans défaut en dur (`AUTH_ISSUER` requis),
événements `auth_discovery_failed` / `auth_jwks_failed` pinés par
`capture_logs`, raisons de rejet en ensemble fermé `Literal` avec une
raison exacte par échec (mapping des erreurs joserfc claim par claim),
assertion réelle sur `close()` (client possédé fermé, client injecté
intact). 3 TO-FIX : garde discovery non-objet, test de propriété
hypothesis, proposition de split dans le corps de la PR (ADR-0019).

## Limites connues

- Niveau L1 uniquement : pas de Zitadel éphémère (L2) ni de surface
  HTTP branchée (PT-2, issue #183) — la brique n'est pas encore câblée
  sur les routes existantes.
- L'introspection des PAT machines (accès CLI/CI) n'est pas dans cette
  brique ; elle relève du flux machine de PT-2.
